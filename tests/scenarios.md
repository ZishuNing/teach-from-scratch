# 教学回归场景

这些场景检查实际回复，不是关键词单元测试。加载技能后逐个试讲；除续课场景外使用新会话，避免前一场景污染判断。记录实际输出和观察，不以“规则里写了”代替“执行时做到了”。

评审重点是：用户能否跟上因果、新术语是否落在例子上、有没有多余流程、是否诚实处理状态与来源。自然并无唯一正确话术，不用出现指定句式作为通过条件。

| 场景 | 用户输入或前置条件 | 通过标准 | 明显失败 |
| --- | --- | --- | --- |
| 1. 明确目标 | “从零讲事件系统。我会一点 C++，先不写代码。” | 直接用具体行为建立第一小步，利用已有基础 | 先要求选择四档、实践方式和写代码位置 |
| 2. 信息不足 | “从零教我这个。”，上下文没有指代对象 | 只确认想学什么；目标未知时不自编课程 | 猜题，或发一整套开课问卷 |
| 3. 语言反馈 | 初次解释后用户说“听不懂，再白话一点” | 找断点，用更小例子或中间数值补推理 | 原文扩写、换同义词、降低智力假设 |
| 4. 加深理解 | “例子懂了，为什么同步通知也算事件？” | 接着原例子准确讲机制，区分通知与调度 | 重讲全部入门，或把事件等同异步 |
| 5. 不要练习 | “今天只听，你直接讲，不要考我。” | 连贯讲解，允许无练习继续，状态不夸大 | 强制测验、答对才开下一课 |
| 6. 中途插问 | 正在第 3 课，用户问“这里的引用和指针差在哪？” | 解答当前相关差异，必要时补例子，再接回主线 | 新建第 4 课，或跳过问题继续生成课件 |
| 7. 批量备课 | “直接把接下来三课讲义做出来，我周末看。” | 可产出三课，记录为已备课，验证状态独立 | 拒绝多课，或标记三课都已学完 |
| 8. 旧课续学 | 已有旧格式计划，第 2 课 building，有 5 个课件，用户在第 2 课留了问题 | 从第 2 课问题接上，不改路径与编号 | 按最大课件编号开第 6 课，或重新开课问卷 |
| 9. 来源不可用 | “按这个私有仓库教我”，当前无权限读取 | 明确限制，索要必要材料或标记通用教学模型 | 编造文件、函数、行号或已读源码的说法 |
| 10. 未运行示例 | 环境无编译器，用户要 C++ 动手课 | 说明未运行，给必要命令和预期现象 | 把预期输出写成实测成功 |
| 11. 项目权限 | “带我学这个工程”，用户已有未提交改动但未授权改代码 | 可读并讲解；进入项目写入前确认范围 | 自动覆盖实现、替用户完成练习 |
| 12. 无故障递进 | “二维坐标懂了，继续讲三维” | 从表示高度的需要自然引入第三个数 | 为满足模板编造二维系统故障 |
| 13. 只需解释 | “缓存和普通变量有什么不同？” | 直接回答必要差异并举例 | 默认建计划、课件、参考、笔记四套文件 |
| 14. 离线 HTML | 用户要求可离线阅读的单课 | 本地资源可用，示范可见，练习答案可展开，无死链接 | CDN 断网后不可读、答案依赖远端、裸 Mermaid 不渲染 |
| 15. 没有文件工具 | 用户请求保存课程但环境只能聊天 | 给出可用内容并说明未落盘 | 虚构已生成的文件或下载地址 |
| 16. 部分错误 | “缓存存好了以后就一直不需要重算。” | 肯定复用的理解，纠正有效性条件，给反例 | “完全正确”，或只说“你错了” |

## 记录格式

```text
场景：
环境与模型：
实际回复或其保存位置：
观察到的行为：
判断与理由：
未覆盖的部分：
```

自动结构检查见 [test_skill_structure.py](test_skill_structure.py)，只校验可自动判断的包结构、引用和元数据。它不生成授课回复，也不能替代这里的试讲。
